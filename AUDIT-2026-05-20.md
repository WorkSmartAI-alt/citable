# citable v0.1.0 — Audit Findings (2026-05-20)

Self-audit by reading every file and tracing the work-smart.ai run. Two questions answered:

1. **Will citable crawl the entire site within the page limit?** Mostly. There are 4 coverage gaps that would cause under-crawling on common site types.
2. **Are there false positives?** Yes, 3 confirmed (1 caught on work-smart.ai itself) and 5 risks not yet implemented. The 90/A score on work-smart.ai was artificially low because the FAQPage check fires on rhetorical `?`-ending H2s.

This document lists all findings, the fix for each, and what is being deferred to v0.2.0.

---

## Confirmed false positives (fix in v0.1.1)

### FP-1 · C-13 FAQPage fires on rhetorical question CTAs

**Symptom:** work-smart.ai scored 90/A with a "1 of 3 pages missing FAQPage" finding. Investigation showed the trigger H2s were all CTAs, not Q&A content:

| Page | H2 | Has FAQPage? |
|------|----|--------------|
| `/methodology` | "Need the compliance gate answered before the first call?" | No (but H2 is a CTA, not a FAQ) |
| `/services/ai-ops-audit` | "Is This You?" | Yes (real FAQ schema for real FAQs elsewhere on page) |
| `/services/ai-foundation-build` | "Is This Right Now?" | Yes (same) |
| `/resources` | "Ready to go beyond the guides?" | No (CTA, not a FAQ) |

**Root cause:** My heuristic `H2 ends in ?` is too aggressive. A single rhetorical question heading does not indicate FAQ content.

**Fix:**
1. Require at least **2 question-ending H2s** before treating a page as Q&A.
2. Require each question H2 to be followed by a paragraph of at least 40 characters (an actual answer, not a CTA button).
3. Lower severity from P0 to P1. FAQPage missing is high-impact when content is genuinely Q&A, but accusing a site of missing schema it does not need is worse than missing one borderline page.

**Expected score change on work-smart.ai:** 90/A → 95-100/A (Schema Markup goes from 50 to 100 because the FAQPage finding evaporates).

### FP-2 · C-15 Organization schema rejects valid sub-types

**Symptom:** work-smart.ai passed C-15 because it ships BOTH `Organization` and `ProfessionalService` in the same `@graph`. A site that only ships `ProfessionalService` (which IS-A Organization per schema.org) would FAIL — false positive.

**Root cause:** My check only matches type strings `Organization` or `LocalBusiness`. Schema.org has 10+ Organization subtypes that all count.

**Fix:** Accept any of:
- Organization
- LocalBusiness
- ProfessionalService
- Corporation
- EducationalOrganization
- GovernmentOrganization
- NGO
- PerformingGroup
- SportsOrganization
- MedicalOrganization
- NewsMediaOrganization

### FP-3 · C-02 wildcard detection misses no-space format

**Symptom:** My wildcard detection uses `"user-agent: *" in robots` (literal substring). robots.txt files in the wild use `User-agent:*` (no space) or `User-agent:\t*` (tab). A site with `User-agent:*\nDisallow:/` blocks every crawler including AI bots, but my check would not detect the wildcard and silently return UNVERIFIED instead of FAIL.

**Fix:** Use `re.search(r"^\s*user-agent\s*:\s*\*", robots, re.M | re.I)`. Also: when wildcard exists AND has `Disallow: /`, emit FAIL ("all crawlers blocked, no AI bot exception"), not UNVERIFIED.

## Coverage gaps (fix in v0.1.1)

### COV-1 · Sitemap-index handling stops at first 5 sub-sitemaps

**Symptom:** A sitemap-index with 50 sub-sitemaps (common on e-commerce, news, large blogs) has URLs only from sub-sitemaps 1-5 considered. If those 5 are an alphabetical or chronological tail, the most important pages are invisible.

**Fix:** Iterate sub-sitemaps until we have at least `max_pages * 3` URLs, then truncate. Caps total sitemap requests at 25 to prevent runaway.

### COV-2 · Non-HTML URLs waste budget

**Symptom:** Sitemap can contain `.pdf`, `.xml`, image URLs. We fetch them, BeautifulSoup parses them as malformed HTML, and they count against `max_pages`. A site that puts 1000 PDF links in sitemap would consume the entire crawl budget on non-pages.

**Fix:** Skip URLs ending in `.pdf .jpg .jpeg .png .gif .webp .svg .ico .css .js .xml .gz .zip .mp4 .mp3 .doc .docx .xlsx`. Apply in both sitemap parsing and homepage link extraction.

### COV-3 · www vs apex treated as different hosts

**Symptom:** If user enters `example.com` (apex) but the sitemap or links use `www.example.com`, `same_host` rejects them all. The result: 1-page crawl.

**Fix:** Normalize hostname by stripping leading `www.` before comparing.

### COV-4 · No depth-2 crawl as final fallback

**Symptom:** A site with no sitemap and a shallow homepage (only links to 3-4 hub pages, then deeper content) gets only 4-5 pages crawled. Real coverage requires following links from those hubs.

**Fix:** If after sitemap + homepage we have under `max_pages / 2` URLs, fetch the first N hub pages and pull their internal links. Cap total fetches at 30 + `max_pages`.

## Other improvements (fix in v0.1.1)

### IMP-1 · Sitemap.xml.gz support

Many CMS export gzipped sitemaps. Detect `.gz` suffix or `Content-Encoding: gzip` header and decompress before parsing.

### IMP-2 · Duplicate homepage fetches

`detect_spa` fetches homepage twice (default UA + Googlebot UA). `discover_urls` calls `fetch_text` for robots/sitemap then `fetch_one` for the homepage-link fallback. `crawl` then fetches the homepage AGAIN to grab HSTS headers. Plus the per-URL crawl loop fetches it once more (root is in the URL list). Total: 5 homepage fetches per audit. Wasteful, and may trip rate limits on small sites.

**Fix:** Cache the Googlebot homepage response from `detect_spa` and reuse for sitemap-fallback link extraction and HSTS header capture.

### IMP-3 · C-11 H1 leniency

Some sites legitimately use 2 H1s (logo + page title) for accessibility. My check fails any page with `> 1 H1`. Should warn, not fail, when multi-H1 is below 20% of pages.

### IMP-4 · Stripe.com B/C calibration check

Stripe scored 77/B (top of expected range). Their FAQPage check passed because the H2 heuristic happened not to trigger. With the FP-1 fix, Stripe will still likely pass FAQPage but be measured more accurately.

## Deferred to v0.2.0 (documented, not fixed now)

These are known limitations to document in the README so users know what citable does NOT do:

| ID | Limitation | Why deferred |
|----|------------|--------------|
| DEF-1 | No JavaScript rendering (e.g. Playwright). SPA sites that don't SSR will appear "empty" to citable | Adds a Chromium dependency + 5-10x slower runs. v0.2.0 candidate |
| DEF-2 | No respect for robots.txt for our own crawling (we read it for reporting only) | Adds complexity, citable runs at low concurrency anyway. Document in README |
| DEF-3 | Render time measured from crawler location, not user location | Inherent to single-shot crawling. Disclose in fix text |
| DEF-4 | No prioritization of important pages within sitemap | Need a heuristic (URL depth, lastmod date, internal-link counts). v0.2.0 |
| DEF-5 | No per-check timeout | Wrapping each check is straightforward, deferred to keep this v0.1.1 patch focused |
| DEF-6 | No HTTPS-only check (separate from HSTS) | v0.2.0, will be C-22 |
| DEF-7 | No structured handling of soft-404 pages (HTTP 200 with 404 body) | Would require LLM call or heuristic over title/content. v0.2.0 |

## How citable handles "I do not know"

This is the spine of the FP shield. Three verdicts give users confidence:

- `pass` — citable found evidence the check is satisfied
- `warn` — partially satisfied, room to improve, not blocking
- `fail` — clear failure with measurable impact on AI visibility
- `na` — check does not apply to this site (e.g. hreflang on monolingual)
- `unverified` — citable saw the evidence but cannot reach a confident verdict (e.g. wildcard-only robots.txt)

The scoring excludes `na` and `unverified` from the denominator. A site cannot lose points for a check that does not apply or for evidence citable would rather flag than guess on.

Most "AI visibility" tools in the market guess. citable does not.
